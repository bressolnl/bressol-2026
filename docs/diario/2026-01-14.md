Día 4 — Plugin modular y tracking base (dataLayer)

Qué se ha hecho:
- Reorganizado el plugin bressol-core a arquitectura modular (Core + Modules)
- Creado bootstrap limpio del plugin con autoload por namespaces
- Definida interfaz ModuleInterface para módulos desacoplados
- Implementado primer módulo real: Tracking
- Garantizado window.dataLayer sin inyectar scripts externos
- Enviado evento base bressol_page_view en todas las páginas
- Cargado asset tracking.js para estandarizar futuros eventos
- Verificado dataLayer en frontend y consola del navegador
- Documentado el sistema de tracking en docs/tracking.md

Qué he aprendido:
- Un plugin profesional no tiene lógica en el archivo principal
- El bootstrap centraliza la carga de módulos
- La arquitectura modular permite escalar sin desorden
- WordPress puede actuar como proveedor de datos (dataLayer) sin gestionar etiquetas
- Usar namespaces evita colisiones y mejora mantenibilidad
