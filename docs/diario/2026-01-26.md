# Día 17 — Modal post-add-to-cart (upsell/upgrade) + reemplazo por pack
Fecha: 2026-01-26

## Qué se ha hecho
- Implementado módulo **PostAddToCartModal** dentro de `bressol-core` (arquitectura modular).
- Añadido el módulo al bootstrap del plugin (`Core/Plugin.php`) para que cargue automáticamente.
- Creado controlador frontend `ModalController` con:
  - Captura del último `add_to_cart` (product_id + cart_item_key + slot detectado por categoría).
  - Endpoint AJAX para obtener **sugerencias post-add-to-cart** (packs upgrade + extras cross-sell).
  - Endpoint AJAX para **reemplazar** el producto recién añadido por un pack (remove original + add pack con `bressol_pack_config`).
  - Endpoint AJAX para añadir extras al carrito desde el modal.
- Añadido `modal.js` con:
  - Apertura del modal tras evento `added_to_cart` (AJAX) y fallback por `pending` para flujos donde no existe ese evento (PDP submit / Blocks).
  - UI de selección de packs y extras, y segundo paso para configurar slots del pack (selects).
  - Envío de `config_json` al servidor para guardar configuración del pack en el carrito.
  - Refresco de mini-cart mediante **Woo fragments** tras acciones del modal.
  - Cooldown para evitar fatiga del usuario; verificación y ajuste durante el testing.
- Validación funcional:
  - El modal aparece tras añadir producto.
  - Se muestran packs compatibles cuando el producto está incluido como opción en el JSON del pack.
  - Al elegir upgrade, el carrito queda con **solo el pack** (no pack + producto suelto).
  - El prefill del slot correcto funciona (se mantiene la selección del producto origen dentro del pack).
  - El flujo completo funciona en local y se ha hecho commit + push.

## Qué he aprendido
- El flujo post-add-to-cart requiere contemplar dos caminos:
  - **AJAX add_to_cart** (evento `added_to_cart`) y
  - **No-AJAX / Blocks** (fallback por estado en sesión y render siguiente).
- Para “upgrade real” la lógica correcta es:
  - Capturar `cart_item_key` del producto añadido,
  - Remover ese item,
  - Añadir el pack con `cart_item_data` (config del pack + metadata de upgrade).
- En WooCommerce, el refresco de UI debe hacerse con **fragments** para no romper mini-cart y evitar inconsistencias visuales.
- El cooldown es crítico para UX: sin control, el modal se vuelve intrusivo.
